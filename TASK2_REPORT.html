1. Objective & Problem Addressed

Objective: To architect, wire, and deploy a secure Internet-of-Things (IoT) automation system that connects an ESP32 microcontroller to the Adafruit IO Cloud platform via the lightweight MQTT (Message Queuing Telemetry Transport) protocol. The system actuates a commercial 230V AC incandescent/LED lamp through an optically isolated 5V electromechanical relay in response to interactive toggle events triggered from a remote web dashboard.

Problem Being Addressed: Local micro-web servers (such as those implemented in basic LAN setups) are strictly constrained to local subnet accessibility. Controlling home appliances from outside the local network typically requires risky public IP exposure, dynamic DNS reconfiguration, or vulnerable router port-forwarding. By implementing an asynchronous Publish/Subscribe broker architecture through Adafruit IO, the ESP32 maintains an outbound-only persistent TCP socket, enabling instantaneous global remote actuation without exposing local firewalls. Furthermore, controlling high-voltage mains electricity necessitates galvanic optocoupler isolation to protect low-voltage 3.3V/5V logic from inductive kickback spikes.

2. Basic Concept of ESP32 Cloud IoT & MQTT Broker

Unlike heavy HTTP request-response transactions that repeatedly open and tear down TCP sessions with high overhead headers, MQTT (Message Queuing Telemetry Transport) is a lightweight binary protocol engineered explicitly for resource-constrained edge microcontrollers and fluctuating radio networks:

Publish / Subscribe Pattern

Devices never communicate directly with each other. Instead, publishers send messages labeled under a specific topic, and subscribers register interest in topics through a centralized broker (Adafruit IO), completely decoupling client connections.

Low Network Overhead

MQTT fixed headers require as little as 2 bytes of packet overhead. This dramatically conserves ESP32 transceiver duty cycle, lowers transmission latency to milliseconds, and reduces memory consumption.

Persistent TCP Keep-Alive

A single long-lived TCP socket remains open over port 1883. Periodic ping() heartbeats ensure continuous channel readiness, allowing instantaneous server-initiated push commands to the relay without client polling.

3. How ESP32 and Adafruit IO Communicate over Wi-Fi / MQTT

Communication between the Adafruit IO Cloud dashboard and the physical ESP32 relay module operates through the following sequence:

[PROTOCOL EXCHANGE TIMELINE]
1. [BOOT] ESP32 boots → Connects to 2.4 GHz 802.11 b/g/n Wi-Fi AP → Obtains Local IP.
2. [CONNECT] Opens TCP socket to io.adafruit.com:1883 → Sends MQTT CONNECT packet with AIO Username & Active Secret Key.
3. [SUBSCRIBE] ESP32 issues SUBSCRIBE packet for feed: <user>/feeds/lamp-switch.
4. [USER ACTION] Operator visits Adafruit IO dashboard → Flips Toggle Switch to ON.
5. [BROKER ROUTE] Adafruit IO broker publishes MQTT packet with payload "ON" (or "1") to the feed topic.
6. [EDGE RX] ESP32 mqtt.readSubscription() catches the payload over the persistent socket.
7. [ACTUATION] Microcontroller drives GPIO 23 LOW → Optocoupler fires → Relay coil energizes → COM connects to NO → 230V AC circuit completes → Bulb turns ON.
8. [TELEMETRY ACK] ESP32 publishes state confirmation payload "BULB_ACTIVE" back to cloud feed <user>/feeds/lamp-status.

7. Complete Arduino/ESP32 Source Code

The production firmware leverages the official Adafruit_MQTT library to manage persistent bi-directional subscriptions with non-blocking polling and automatic reconnection:

task2_esp32_adafruitio_relay.ino Download .ino 
#include <WiFi.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"

// ======================== WI-FI CONFIGURATION ========================
#define WLAN_SSID       "YOUR_WIFI_SSID"      // Wi-Fi Access Point SSID
#define WLAN_PASS       "YOUR_WIFI_PASSWORD"  // Wi-Fi Password

// ===================== ADAFRUIT IO CONFIGURATION =====================
#define AIO_SERVER      "io.adafruit.com"
#define AIO_SERVERPORT  1883                  // Standard MQTT Port
#define AIO_USERNAME    "YOUR_AIO_USERNAME"  // Adafruit IO Username
#define AIO_KEY         "YOUR_AIO_KEY"       // Adafruit IO Active Secret Key

// ======================== PIN DEFINITIONS ============================
const int RELAY_PIN    = 23;  // GPIO 23 connected to Relay IN pin
const int STATUS_LED   = 2;   // Built-in Blue LED for visual status

// Active-LOW relay module logic definition
#define RELAY_ON   LOW
#define RELAY_OFF  HIGH

// Instantiate Wi-Fi and MQTT Client instances
WiFiClient client;
Adafruit_MQTT_Client mqtt(&client, AIO_SERVER, AIO_SERVERPORT, AIO_USERNAME, AIO_KEY);

// Setup Adafruit IO Subscription Feed
Adafruit_MQTT_Subscribe lampFeed = Adafruit_MQTT_Subscribe(&mqtt, AIO_USERNAME "/feeds/lamp-switch");
// Setup Adafruit IO Publishing Feed for telemetry acknowledgment
Adafruit_MQTT_Publish statusFeed = Adafruit_MQTT_Publish(&mqtt, AIO_USERNAME "/feeds/lamp-status");

void MQTT_connect();

void setup() {
  Serial.begin(115200);
  delay(100);

  Serial.println(F("\n--- ESP32 & Adafruit IO Cloud Lamp Controller ---"));
  Serial.println(F("Author: Hemavarshini S N | Mechatronics Engineering, KCT\n"));

  pinMode(RELAY_PIN, OUTPUT);
  pinMode(STATUS_LED, OUTPUT);

  // Safety default: Ensure appliance starts in de-energized OFF state
  digitalWrite(RELAY_PIN, RELAY_OFF);
  digitalWrite(STATUS_LED, LOW);

  // Establish Wi-Fi Association
  Serial.print(F("Connecting to Wi-Fi SSID: "));
  Serial.println(WLAN_SSID);
  WiFi.mode(WIFI_STA);
  WiFi.begin(WLAN_SSID, WLAN_PASS);

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(F("."));
    digitalWrite(STATUS_LED, !digitalRead(STATUS_LED));
  }

  digitalWrite(STATUS_LED, LOW);
  Serial.println(F("\n[SUCCESS] Wi-Fi Associated!"));
  Serial.print(F("Node Assigned IP Address: "));
  Serial.println(WiFi.localIP());

  // Register MQTT Feed Subscription
  mqtt.subscribe(&lampFeed);
  Serial.println(F("Subscribed to Adafruit IO Feed: 'lamp-switch'"));
}

void loop() {
  // Ensure connection persistence
  MQTT_connect();

  // Read incoming cloud subscription messages (non-blocking 1000ms window)
  Adafruit_MQTT_Subscribe *subscription;
  while ((subscription = mqtt.readSubscription(1000))) {
    if (subscription == &lampFeed) {
      char *command = (char *)lampFeed.lastread;
      Serial.print(F("\n[MQTT RX] Received Cloud Payload: "));
      Serial.println(command);

      if (strcmp(command, "ON") == 0 || strcmp(command, "1") == 0) {
        digitalWrite(RELAY_PIN, RELAY_ON);   // Trigger Active-LOW Relay
        digitalWrite(STATUS_LED, HIGH);
        Serial.println(F(">>> RELAY ENERGIZED: 230V AC Lamp is ON"));
        statusFeed.publish("BULB_ACTIVE");
      } 
      else if (strcmp(command, "OFF") == 0 || strcmp(command, "0") == 0) {
        digitalWrite(RELAY_PIN, RELAY_OFF);  // De-energize Relay
        digitalWrite(STATUS_LED, LOW);
        Serial.println(F(">>> RELAY DE-ENERGIZED: 230V AC Lamp is OFF"));
        statusFeed.publish("BULB_INACTIVE");
      }
    }
  }

  // Broker keep-alive ping
  if (!mqtt.ping()) {
    mqtt.disconnect();
  }
}

void MQTT_connect() {
  int8_t ret;
  if (mqtt.connected()) return;

  Serial.print(F("Connecting to Adafruit IO MQTT Broker... "));
  uint8_t retries = 5;

  while ((ret = mqtt.connect()) != 0) {
    Serial.println(mqtt.connectErrorString(ret));
    Serial.println(F("Retrying MQTT connection in 5 seconds..."));
    mqtt.disconnect();
    delay(5000);
    retries--;
    if (retries == 0) {
      Serial.println(F("[ERROR] Unable to reach Adafruit IO broker."));
      return;
    }
  }
  Serial.println(F("[SUCCESS] Adafruit IO MQTT Connected & Listening!"));
}

9. How the Webpage Sends Commands to the ESP32

When the operator clicks the switch button on the web dashboard, the actuation pipeline executes across four architectural tiers:

  1. Client Event Capture: The browser DOM captures the click event on the toggle component and sends an asynchronous WebSocket message (or REST API POST) to io.adafruit.com.
  2. Broker Message Dispatch: The Adafruit IO MQTT broker immediately translates this event into an MQTT PUBLISH packet targeted at topic <username>/feeds/lamp-switch.
  3. Socket Arrival & Header Parsing: The ESP32's non-blocking network thread retrieves the payload from the established TCP buffer without needing to poll or reload.
  4. Electromechanical Switching: The firmware evaluates strcmp(command, "ON"), pulls GPIO 23 to 0V (LOW), energizing the relay coil via the optocoupler and lighting the 230V AC lamp in under 180 milliseconds end-to-end.

13. Problems Encountered & How They Were Solved

⚠️ Issue 1: Active-LOW Relay Logic Inversion

Initially, writing digitalWrite(RELAY_PIN, HIGH) left the relay off, while writing LOW turned it on, causing reversed operation compared to standard digital logic.

✅ Solution Implemented

Recognized the optocoupler PNP circuit is Active-LOW. Defined clean semantic constants #define RELAY_ON LOW and #define RELAY_OFF HIGH to ensure readable, safe code.

⚠️ Issue 2: MQTT Keep-Alive Timeout Drops

After periods of operator inactivity, Adafruit IO terminated the socket due to missed heartbeats, preventing subsequent toggle clicks from reaching the ESP32.

✅ Solution Implemented

Added a mqtt.ping() keep-alive pulse inside loop(), paired with an automated non-blocking MQTT_connect() reconnection watchdog routine.

⚠️ Issue 3: Inductive AC Voltage Spikes

Switching 230V AC loads produces electromagnetic noise and back-EMF that can induce brownout resets on the ESP32 3.3V rail.

✅ Solution Implemented

Utilized an optically isolated relay board with a flyback diode across the coil, routing AC high-voltage wiring physically isolated from the ESP32 breadboard logic.

⚠️ Issue 4: Bootloader GPIO Strapping Conflicts

Using GPIO 0 or GPIO 12 for the relay caused bootloader failure or relay chattering during microcontroller power-up.

✅ Solution Implemented

Migrated relay control exclusively to GPIO 23, an unstrapped general-purpose I/O pin with stable high-impedance state during ESP32 initialization.
