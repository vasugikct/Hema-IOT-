1. Objective & Problem Addressed

Objective: To engineer and demonstrate an integrated voice-activated Internet-of-Things (IoT) automation system enabling touchless natural-language control of physical domestic electrical appliances. The architecture connects Google Assistant Voice Scenes to an IFTTT (If This Then That) cloud webhook pipeline, which dispatches state updates to an Adafruit IO MQTT broker. An edge ESP32 SoC listens for these events and actuates a 230V AC lamp via a 5V optoisolated relay module.

Problem Being Addressed: While web dashboards (such as those created in Tasks 1 and 2) provide remote visual telemetry, they require users to physically interact with a smartphone or PC screen—unlocking devices, navigating to URLs, and tapping buttons. This introduces friction in everyday home and industrial automation, and creates substantial accessibility barriers for elderly individuals, visually impaired users, or operators whose hands are occupied with mechanical tasks. Direct integration between consumer voice platforms (Google Assistant) and edge microcontrollers (ESP32) is traditionally hindered by proprietary APIs and complex OAuth2 security tokens. By architecting an intermediary middleware pipeline using IFTTT applets and Adafruit IO MQTT feeds, natural language utterances ("Ok Google, activate lights on") are converted into deterministic physical switching actions with low latency and zero local server infrastructure.

2. Basic Concept of Voice UI & IFTTT Webhook Cloud Architecture

Building a voice-actuated cyber-physical system requires bridging four distinct software abstraction layers, each specialized in a distinct operational tier:

1. Voice Recognition (Google Assistant)

Translates acoustic sound waves into intent-recognized text tokens. Configured with specific named scenes (e.g. "lights on" and "lights off") to eliminate natural language ambiguity.

2. Webhook Event Engine (IFTTT)

Acts as the integration glue. When the Google Assistant trigger fires, IFTTT executes an outbound HTTPS REST POST containing the desired command payload targeted at Adafruit IO's cloud API.

3. MQTT Message Broker (Adafruit IO)

Converts incoming HTTP webhook REST data into lightweight MQTT packets, broadcasting them instantly across the subscribed feed lamp-switch over an open TCP socket.

4. Edge Microcontroller (ESP32)

Maintains the socket connection, parses the payload string, and outputs digital 3.3V logic to the relay module's optocoupler to physically switch the 230V AC lamp.

3. Multi-Cloud Protocol Communication Flow

The end-to-end telemetry lifecycle from spoken human utterance to physical light emission involves the following cross-cloud protocol exchanges:

[MULTI-TIER PROTOCOL DISPATCH TIMELINE]
1. [VOICE UTTERANCE] User speaks: "Ok Google, activate lights on".
2. [SPEECH RECOGNITION] Google Assistant NLP parses phonemes → Identifies registered Scene: "lights on".
3. [CLOUD WEBHOOK] Google Cloud invokes IFTTT Partner API webhook via secure OAuth2 token.
4. [IFTTT RULE EVALUATION] IFTTT Applet triggers: If [Google Assistant Scene == "lights on"].
5. [THEN THAT DISPATCH] IFTTT issues HTTPS POST request to Adafruit IO REST API: POST https://io.adafruit.com/api/v2/{username}/feeds/lamp-switch/data with JSON payload: {"value": "ON"}.
6. [BROKER ROUTE] Adafruit IO ingests payload → Converts to MQTT PUBLISH packet on topic {username}/feeds/lamp-switch.
7. [TCP SOCKET ARRIVAL] ESP32's mqtt.readSubscription() receives the packet over Wi-Fi port 1883.
8. [RELAY TRIGGER] ESP32 matches "ON" → Drives GPIO 23 LOW → Relay energizes → 230V AC lamp illuminates.
9. [CONFIRMATION TELEMETRY] ESP32 publishes "VOICE_TRIGGERED_ON" back to lamp-status feed for audit logging.

#include <WiFi.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"

// ======================== WI-FI CONFIGURATION ========================
#define WLAN_SSID       "YOUR_WIFI_SSID"      // Local Wi-Fi Access Point
#define WLAN_PASS       "YOUR_WIFI_PASSWORD"  // Wi-Fi Password

// ===================== ADAFRUIT IO CONFIGURATION =====================
#define AIO_SERVER      "io.adafruit.com"
#define AIO_SERVERPORT  1883                  // Standard MQTT Port
#define AIO_USERNAME    "YOUR_AIO_USERNAME"  // Adafruit IO Username
#define AIO_KEY         "YOUR_AIO_KEY"       // Adafruit IO Active Key

// ======================== PIN DEFINITIONS ============================
const int RELAY_PIN    = 23;  // GPIO 23 connected to Relay IN pin
const int STATUS_LED   = 2;   // Onboard Blue Status LED

// Active-LOW relay logic definitions
#define RELAY_ON   LOW
#define RELAY_OFF  HIGH

bool lampState = false;

WiFiClient client;
Adafruit_MQTT_Client mqtt(&client, AIO_SERVER, AIO_SERVERPORT, AIO_USERNAME, AIO_KEY);

// Feed subscribed to receive data from IFTTT Applet triggered by Google Assistant
Adafruit_MQTT_Subscribe voiceFeed = Adafruit_MQTT_Subscribe(&mqtt, AIO_USERNAME "/feeds/lamp-switch");
// Telemetry publishing feed
Adafruit_MQTT_Publish statusFeed = Adafruit_MQTT_Publish(&mqtt, AIO_USERNAME "/feeds/lamp-status");

void MQTT_connect();

void setup() {
  Serial.begin(115200);
  delay(100);

  Serial.println(F("\n--- Google Assistant & IFTTT Voice IoT Relay Controller ---"));
  Serial.println(F("Author: Hemavarshini S N | Mechatronics Engineering, KCT\n"));

  pinMode(RELAY_PIN, OUTPUT);
  pinMode(STATUS_LED, OUTPUT);

  // Safety default: Ensure appliance starts in de-energized OFF state
  digitalWrite(RELAY_PIN, RELAY_OFF);
  digitalWrite(STATUS_LED, LOW);

  // Establish Wi-Fi Association
  Serial.print(F("Connecting to Wi-Fi SSID: "));
  Serial.println(WLAN_SSID);
  WiFi.mode(WIFI_STA);
  WiFi.begin(WLAN_SSID, WLAN_PASS);

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(F("."));
    digitalWrite(STATUS_LED, !digitalRead(STATUS_LED));
  }

  digitalWrite(STATUS_LED, LOW);
  Serial.println(F("\n[SUCCESS] Wi-Fi Associated!"));
  Serial.print(F("ESP32 Local IP: "));
  Serial.println(WiFi.localIP());

  // Subscribe to Voice Feed target
  mqtt.subscribe(&voiceFeed);
  Serial.println(F("Subscribed to MQTT Feed: 'lamp-switch' (IFTTT Target)"));
}

void loop() {
  // Ensure connection persistence
  MQTT_connect();

  // Read incoming cloud subscription messages (non-blocking 1000ms window)
  Adafruit_MQTT_Subscribe *subscription;
  while ((subscription = mqtt.readSubscription(1000))) {
    if (subscription == &voiceFeed) {
      char *payload = (char *)voiceFeed.lastread;
      Serial.print(F("\n[VOICE CLOUD EVENT] Incoming IFTTT Payload: "));
      Serial.println(payload);

      // Evaluate voice trigger payload (case-insensitive string checks)
      if (strcmp(payload, "ON") == 0 || strcmp(payload, "1") == 0 || strcasecmp(payload, "lights on") == 0) {
        digitalWrite(RELAY_PIN, RELAY_ON);   // Trigger Active-LOW Relay
        digitalWrite(STATUS_LED, HIGH);
        lampState = true;
        Serial.println(F(">>> [VOICE ACTION: ON] Google Assistant Triggered -> Lamp ON"));
        statusFeed.publish("VOICE_TRIGGERED_ON");
      } 
      else if (strcmp(payload, "OFF") == 0 || strcmp(payload, "0") == 0 || strcasecmp(payload, "lights off") == 0) {
        digitalWrite(RELAY_PIN, RELAY_OFF);  // De-energize Relay
        digitalWrite(STATUS_LED, LOW);
        lampState = false;
        Serial.println(F(">>> [VOICE ACTION: OFF] Google Assistant Triggered -> Lamp OFF"));
        statusFeed.publish("VOICE_TRIGGERED_OFF");
      }
    }
  }

  // Broker keep-alive ping
  if (!mqtt.ping()) {
    mqtt.disconnect();
  }
}

void MQTT_connect() {
  int8_t ret;
  if (mqtt.connected()) return;

  Serial.print(F("Connecting to Adafruit IO MQTT Broker... "));
  uint8_t retries = 5;

  while ((ret = mqtt.connect()) != 0) {
    Serial.println(mqtt.connectErrorString(ret));
    Serial.println(F("Retrying MQTT connection in 5 seconds..."));
    mqtt.disconnect();
    delay(5000);
    retries--;
    if (retries == 0) {
      Serial.println(F("[ERROR] Unable to reach broker. Continuing loop..."));
      return;
    }
  }
  Serial.println(F("[SUCCESS] Adafruit IO Connected & Ready for Voice Events!"));
}

9. Speech-to-Actuator Dispatch Mechanism

The end-to-end execution sequence from voice utterance to physical switching executes across five structured stages:

  1. Acoustic Voice Parsing: The user speaks "Ok Google, activate lights on". The on-device Google Assistant neural net performs speech-to-intent parsing and invokes the matching registered Scene.
  2. Cloud Webhook Dispatch: Google Cloud's automation service invokes the IFTTT webhook endpoint over HTTPS.
  3. REST API Transmission: The IFTTT Applet executes the "Send data to Adafruit IO" action block, making an authenticated REST call to io.adafruit.com with payload "ON".
  4. MQTT Broker Broadcasting: Adafruit IO receives the REST update and immediately pushes it as an MQTT PUBLISH message to topic lamp-switch.
  5. Edge Microcontroller Actuation: The ESP32's open TCP socket catches the packet. The firmware extracts payload "ON", drives GPIO 23 LOW, and the relay's physical armature snaps closed, illuminating the 230V AC lamp in approximately 1.2 seconds end-to-end.

13. Problems Encountered & How They Were Solved

⚠️ Issue 1: Google Assistant Utterance Ambiguity

Standard phrases like "turn on lights" were frequently intercepted by Google Home's default smart home device search, failing to trigger the custom applet.

✅ Solution Implemented

Configured Google Assistant Scene Triggers invoked via "activate [Scene Name]" (e.g. "activate lights on"), bypassing generic device routing.

⚠️ Issue 2: Multi-Cloud Webhook Latency Jitter

Occasional routing delays between Google Cloud, IFTTT servers, and Adafruit IO resulted in a 2 to 3 second command lag.

✅ Solution Implemented

Utilized IFTTT Pro Realtime Triggers and streamlined the Adafruit IO feed pipeline to reduce queue hops, stabilizing latency around 1.1–1.4 seconds.

⚠️ Issue 3: Inconsistent Payload String Formatting

Different IFTTT applet actions sent varying payloads (e.g., "ON" vs. "lights on" vs. "1"), causing string comparison mismatches in firmware.

✅ Solution Implemented

Implemented flexible multi-condition payload evaluation using both strcmp() and case-insensitive strcasecmp() to handle multiple valid trigger strings.

⚠️ Issue 4: Socket Dropout During Extended Inactivity

When no voice commands were spoken for over 5 minutes, the TCP connection between ESP32 and Adafruit IO timed out quietly.

✅ Solution Implemented

Integrated an automatic mqtt.ping() heartbeat in the main loop combined with a resilient MQTT_connect() auto-reconnect routine.
