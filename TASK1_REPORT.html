1. Objective & Problem Addressed

Objective: To design, assemble, program, and validate an embedded standalone web server on the ESP32 System-on-Chip (SoC) operating over an 802.11b/g/n Wi-Fi local area network (LAN). The system hosts a custom-styled, responsive HTML user interface capable of dispatching commands to toggle a physical Light Emitting Diode (LED) on and off in real time without external cloud brokers.

Problem Being Addressed: Traditional electromechanical systems rely on hardwired tactile switches, which limit accessibility, increase wiring harness bulk, and make remote diagnostic oversight impossible. While commercial IoT solutions exist, they often rely on third-party public cloud servers (e.g., AWS IoT, Google Cloud, Tuya), introducing transmission latency, external dependency, privacy concerns, and recurring costs. By establishing a direct, local socket server on the edge hardware itself, this project delivers instantaneous, intranet-contained device control with zero cloud subscriptions.

2. Basic Concept of an ESP32 Web Server

The ESP32 is a low-cost, low-power system-on-chip with integrated Wi-Fi and dual-mode Bluetooth (Tensilica Xtensa dual-core 32-bit LX6 microprocessor operating up to 240 MHz). Through the Arduino ESP32 core networking stack:

  • Station (STA) Mode: The ESP32 associates with an existing Wi-Fi Access Point (router) using WPA2-PSK authentication and acquires a local IP address via DHCP (e.g., 192.168.x.x).
  • TCP Socket Listener: A WiFiServer object binds to standard HTTP TCP port 80 and enters an event loop listening for incoming TCP handshake requests.
  • Daemon Loop: When a network client (e.g., laptop or smartphone browser) navigates to the ESP32's IP address, the server accepts the socket connection, reads raw incoming ASCII character streams, handles the requested URI, and flushes an HTTP-compliant response packet back to the client.

3. How ESP32 and Browser Communicate over Wi-Fi

Communication is founded on the classic Client-Server Request-Response model over the TCP/IP protocol suite:

Step Entity Protocol Layer Transaction Details
1. Network Join ESP32 & WLAN AP 802.11 / DHCP ESP32 connects to Wi-Fi SSID, negotiates IP (e.g. 192.168.1.105), and spins up TCP socket on Port 80.
2. Client Request Web Browser HTTP / TCP User enters IP or taps a button. Browser opens TCP socket to port 80 and transmits HTTP GET line: GET /H HTTP/1.1\r\n.
3. Payload Parsing ESP32 Firmware Application Layer ESP32 buffers incoming characters until double newline (\r\n\r\n) and executes URI routing logic: detects /H or /L.
4. Actuation ESP32 Microcontroller Hardware GPIO Firmware calls digitalWrite(ledPin, HIGH); GPIO pin potential jumps to 3.3V, forward-biasing the LED.
5. HTTP Response ESP32 Server HTTP / HTML Returns HTTP/1.1 200 OK headers, closes connection, and streams HTML payload with updated visual status.

7. Complete Arduino/ESP32 Source Code

Production-tested, complete sketch written in C++ for the Arduino ESP32 Board package. It initializes non-blocking HTTP socket handling, parses incoming GET parameters, toggles GPIO 2, and renders the responsive UI.

task1_esp32_webserver_led.ino — Arduino C++ 
/*
  =============================================================================
  Project     : ESP32 Web Server & HTML LED Control (IoT Task 1)
  Author      : Vasugi D (B.E. Mechatronics Engineering, KCT)
  Description : Standalone HTTP Web Server running on ESP32 to remotely control
                an LED actuator over a local Wi-Fi intranet.
  Hardware    : ESP32 DevKit V1, 5mm LED, 220 Ohm Resistor, Breadboard
  Pin Wiring  : GPIO 2 -> 220 Ohm Resistor -> LED Anode (+) | LED Cathode (-) -> GND
  =============================================================================
*/

#include <WiFi.h>

// ---------- Wi-Fi Credentials ----------
const char* ssid     = "YOUR_WIFI_SSID";     // Replace with local Wi-Fi SSID
const char* password = "YOUR_WIFI_PASSWORD"; // Replace with local Wi-Fi Password

// ---------- Web Server Configuration ----------
WiFiServer server(80); // Bind server to standard HTTP port 80

// ---------- Hardware Pin Definitions ----------
const int ledPin = 2;  // GPIO 2 (Connected to external LED + Onboard Blue LED)

// State Variables
String ledState = "OFF";
String header;

// Non-blocking timeout parameters
unsigned long currentTime = millis();
unsigned long previousTime = 0;
const long timeoutTime = 2000; // 2000 ms client inactivity limit

void setup() {
  Serial.begin(115200);
  delay(100);

  // Initialize GPIO 2 as digital output and set default to LOW (OFF)
  pinMode(ledPin, OUTPUT);
  digitalWrite(ledPin, LOW);

  // Initiate Wi-Fi Connection in Station (STA) Mode
  Serial.println();
  Serial.print("[Wi-Fi] Connecting to ");
  Serial.println(ssid);
  WiFi.begin(ssid, password);

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  // Print DHCP IP Address
  Serial.println("");
  Serial.println("[Wi-Fi] Connected successfully!");
  Serial.print("[Wi-Fi] Server URL: http://");
  Serial.println(WiFi.localIP());

  // Start HTTP Daemon
  server.begin();
  Serial.println("[Server] HTTP Server listening on port 80.");
}

void loop() {
  // Listen for incoming TCP client requests
  WiFiClient client = server.available();

  if (client) {
    currentTime = millis();
    previousTime = currentTime;
    Serial.println("[Client] Inbound connection accepted.");
    String currentLine = "";

    while (client.connected() && currentTime - previousTime <= timeoutTime) {
      currentTime = millis();
      if (client.available()) {
        char c = client.read();
        Serial.write(c);
        header += c;

        if (c == '\n') {
          // If the line is empty, two newline chars indicate the end of HTTP request
          if (currentLine.length() == 0) {
            // Send standard HTTP response status code
            client.println("HTTP/1.1 200 OK");
            client.println("Content-type:text/html");
            client.println("Connection: close");
            client.println();

            // Command parsing logic
            if (header.indexOf("GET /H") >= 0) {
              Serial.println("[Command] Turning LED ON (GPIO 2 -> HIGH)");
              ledState = "ON";
              digitalWrite(ledPin, HIGH);
            } else if (header.indexOf("GET /L") >= 0) {
              Serial.println("[Command] Turning LED OFF (GPIO 2 -> LOW)");
              ledState = "OFF";
              digitalWrite(ledPin, LOW);
            }

            // Stream responsive HTML UI payload
            client.println("<!DOCTYPE html><html>");
            client.println("<head><meta name=\"viewport\" content=\"width=device-width, initial-scale=1\">");
            client.println("<link rel=\"icon\" href=\"data:,\">");
            client.println("<style>");
            client.println("html { font-family: sans-serif; text-align: center; background: #070e17; color: #e8eef4; }");
            client.println("body { margin: 0; padding: 2rem 1rem; display: flex; flex-direction: column; align-items: center; justify-content: center; min-height: 90vh; }");
            client.println(".card { background: #0e1b29; border: 1px solid rgba(255,255,255,0.1); border-radius: 20px; padding: 2.2rem; max-width: 420px; width: 100%; box-shadow: 0 20px 40px rgba(0,0,0,0.5); }");
            client.println("h1 { font-size: 1.8rem; margin: 0 0 0.5rem; color: #4a9ee8; }");
            client.println(".status-box { background: rgba(255,255,255,0.04); border-radius: 12px; padding: 1rem; margin-bottom: 2rem; border: 1px solid rgba(255,255,255,0.06); }");
            client.println(".status-indicator { display: inline-block; width: 12px; height: 12px; border-radius: 50%; margin-right: 8px; }");
            client.println(".state-on { color: #3dcc8e; font-weight: bold; font-size: 1.3rem; }");
            client.println(".state-off { color: #e85a5a; font-weight: bold; font-size: 1.3rem; }");
            client.println(".btn { display: inline-block; width: 100%; box-sizing: border-box; text-decoration: none; padding: 16px; font-size: 1.1rem; font-weight: 600; border-radius: 12px; margin-bottom: 12px; }");
            client.println(".btn-on { background: #3dcc8e; color: #04121a; }");
            client.println(".btn-off { background: #e85a5a; color: #fff; }");
            client.println("</style></head>");
            
            client.println("<body>");
            client.println("<div class=\"card\">");
            client.println("<h1>ESP32 LED Controller</h1>");
            client.println("<p style=\"color:#93a5b5; margin-bottom:1.5rem;\">Vasugi D · IoT Task 1</p>");
            
            client.println("<div class=\"status-box\">");
            client.print("<p style=\"margin:0 0 6px; font-size: 0.85rem; color: #93a5b5;\">CURRENT LED STATE</p>");
            if (ledState == "ON") {
              client.println("<span class=\"status-indicator\" style=\"background:#3dcc8e; box-shadow:0 0 10px #3dcc8e;\"></span>");
              client.println("<span class=\"state-on\">ON</span>");
            } else {
              client.println("<span class=\"status-indicator\" style=\"background:#e85a5a;\"></span>");
              client.println("<span class=\"state-off\">OFF</span>");
            }
            client.println("</div>");

            client.println("<a href=\"/H\" class=\"btn btn-on\">TURN ON LED</a>");
            client.println("<a href=\"/L\" class=\"btn btn-off\">TURN OFF LED</a>");
            client.println("</div></body></html>");

            client.println();
            break;
          } else {
            currentLine = "";
          }
        } else if (c != '\r') {
          currentLine += c;
        }
      }
    }

    header = "";
    client.stop();
    Serial.println("[Client] Connection terminated cleanly.\n");
  }
}

9. How the Webpage Sends a Command to the ESP32

The command execution pipeline functions as follows:

  1. Hyperlink Trigger: Each control element on the HTML interface is an anchor tag with a relative route: <a href="/H"> for ON and <a href="/L"> for OFF.
  2. HTTP Request Generation: When tapped, the browser sends an HTTP packet containing the route header: GET /H HTTP/1.1.
  3. Header String Buffer: In firmware, characters are appended to header += c;.
  4. Pattern Match Routing: The firmware evaluates header.indexOf("GET /H") >= 0. If satisfied, it invokes the hardware abstraction layer: digitalWrite(ledPin, HIGH); and updates ledState = "ON".
  5. State Persistence: The updated state is rendered into the subsequent HTML generation pass, so the user receives visual confirmation on their screen.

13. Problems Encountered and How They Were Solved

⚠️ Issue 1: DHCP Dynamic IP Drift

Upon reboot or router lease renewal, the ESP32 received changing IP addresses, causing the browser bookmarks to break.

✅ Solution Implemented

Configured Serial Monitor IP reporting at 115200 baud during startup and mapped static IP bindings (WiFi.config(staticIP, gateway, subnet)) for persistent addressing.

⚠️ Issue 2: Browser Favicon & Pre-fetch Requests

Modern mobile browsers automatically fire secondary requests for /favicon.ico, which corrupted command string parsing.

✅ Solution Implemented

Injected an inline null favicon link <link rel="icon" href="data:,"> into the HTML <head> to suppress unnecessary secondary HTTP requests.

⚠️ Issue 3: Socket Hang on Client Disconnect

If a mobile device locked its screen before closing the socket, the ESP32 thread stalled in an infinite while loop.

✅ Solution Implemented

Implemented a non-blocking timeout guard using millis() (capped at 2000 ms) to terminate hanging client sessions gracefully with client.stop().

⚠️ Issue 4: GPIO Bootloader Strapping Flashing

Connecting certain pins caused bootloader failure or constant rebooting during flashing.

✅ Solution Implemented

Avoided input-only pins (GPIO 34-39) and strapping pins (GPIO 0, 12, 15), selecting GPIO 2 which provides safe digital output behavior post-boot.

14. Reflection on What I Learned

Building this project provided foundational insight into how software protocols interact directly with bare-metal silicon:

  • Demystifying IoT Networking: I gained a deep appreciation for the HTTP application layer. Seeing an HTTP GET header parsed character-by-character from a TCP socket reinforced how modern smart devices interpret web interactions.
  • Resource-Constrained Architecture: Unlike server-side web development in Node.js or Python with gigabytes of RAM, programming a web server on an embedded MCU requires strict memory discipline, string buffer management, and non-blocking timeout handling.
  • Bridging Mechatronics & Software: As a Mechatronics student, this experiment forms the baseline for remote actuator control—laying the direct path toward industrial SCADA interfaces, wireless robotics teleoperation, and edge IoT monitoring.
